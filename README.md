# Spring Boot 4 + PostgreSQL + Swagger/OpenAPI + Serenity + Cucumber + JUnit 6 Demo

This repository contains a working example of a modern **Spring Boot 4.1.0 / Java 25** application using **PostgreSQL in Docker**, **Gradle 9.6.0**, **Eclipse 2026-06**, **Swagger/OpenAPI through springdoc**, and automated testing with **JUnit 6**, **Cucumber**, and **Serenity BDD**.

The goal is not to teach every technology from scratch. Instead, this project provides a small but realistic baseline where all of these tools work together in one coherent setup. It can be used as a reference project for experimenting with Spring Boot 4, Java 25, PostgreSQL, modern Gradle builds, API documentation, and graphical test reporting.

## Why This Project Exists

Finding a working combination of recent versions across Spring Boot, Java, Gradle, PostgreSQL, Swagger/OpenAPI, Serenity, Cucumber, and JUnit can take time. Online examples are often outdated or use incompatible combinations.

This project demonstrates one working combination that was compiled, executed, tested, and validated locally. AI tools were used as fast technical collaborators during development, but generated code and configuration were reviewed, corrected, compiled, and tested manually.

## Application Overview

The application manages a simple `book` table in PostgreSQL.

```sql
CREATE TABLE book (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    title VARCHAR(200) NOT NULL,
    author VARCHAR(120) NOT NULL,
    isbn VARCHAR(20) NOT NULL,
    published_date DATE,
    price NUMERIC(10, 2),
    stock_quantity INTEGER NOT NULL,
    description VARCHAR(1000),
    CONSTRAINT uk_book_isbn UNIQUE (isbn),
    CONSTRAINT ck_book_price_nonnegative CHECK (price IS NULL OR price >= 0),
    CONSTRAINT ck_book_stock_nonnegative CHECK (stock_quantity >= 0)
);
```

The REST API supports:

- Listing all books.
- Creating a new book.
- Finding a book by numeric database id.
- Updating an existing book.
- Deleting a book by id.
- Searching books by author text, case-insensitively.
- Finding a book by ISBN.

Swagger UI is used to explore and manually test the API. Serenity and Cucumber are used to demonstrate automated API/BDD reporting.

## PostgreSQL Docker Setup

Pull the latest PostgreSQL image:

```bash
docker pull postgres:latest
```

Create and start the PostgreSQL container:

```bash
docker run --name pg-akrivitsky -e POSTGRES_USER=akrivitsky -e POSTGRES_PASSWORD=your_password_here -e POSTGRES_DB=swagger_demo -p 5432:5432 -v pgdata_akrivitsky:/var/lib/postgresql -d postgres:latest
```

Important note for PostgreSQL 18+ Docker images: the persistent volume is mounted at:

```text
/var/lib/postgresql
```

This is the correct mount location for persistent database storage for the PostgreSQL 18+ Docker image used in this project.

Verify the PostgreSQL version:

```bash
docker exec -it pg-akrivitsky psql -U akrivitsky -d swagger_demo
```

Expected version in the article:

```text
psql (18.4 (Debian 18.4-1.pgdg13+1))
```

Verify the Docker volume mount:

```bash
docker inspect pg-akrivitsky --format "{{json .Mounts}}"
```

The important part of the output should be:

```json
"Destination":"/var/lib/postgresql"
```

## Important Files

### `settings.gradle`

Configures the root Gradle project and includes the `lib` subproject. It also applies the Foojay toolchain resolver convention plugin, which allows Gradle to auto-provision JDK 25 together with the Java toolchain declaration in `build.gradle`.

### `build.gradle`

Configures:

- Java 25 toolchain support.
- Spring Boot 4.1.0.
- PostgreSQL JDBC driver.
- springdoc OpenAPI / Swagger UI.
- JUnit 6 / JUnit Jupiter testing.
- Cucumber feature-file testing.
- Serenity BDD reporting.

Although the Serenity artifact is named `serenity-junit5`, it is used here with JUnit 6 because it integrates with the JUnit Jupiter extension model. JUnit Jupiter remains the modern test API used by annotations such as `@Test` and `@ExtendWith`.

### `application.yaml`

Configures the datasource, JPA validation, SQL initialization, virtual threads, and springdoc paths.

Notable settings include:

```yaml
spring:
  threads:
    virtual:
      enabled: true
```

and springdoc paths such as:

```yaml
springdoc:
  swagger-ui:
    path: /swagger-ui.html
  api-docs:
    path: /v3/api-docs
```

If Eclipse marks valid Spring Boot properties such as `server.port` or `springdoc.*` as “not allowed” in `application.yaml`, check the YAML schema validation settings. In the article, Wild Web Developer incorrectly applied an Enonic XP schema from SchemaStore. Disabling automatic YAML schema pulling from JSON Schema Store removed the false validation errors.

### `schema.sql` and `data.sql`

`schema.sql` creates the `book` table. `data.sql` inserts sample books for immediate API testing.

### Main Java Components

- `SwaggerDemoApplication.java` — Spring Boot application entry point.
- `OpenApiConfig.java` — OpenAPI metadata and server configuration.
- `Book.java` — JPA entity mapped to the `book` table.
- DTO records — request/response payloads with validation and schema annotations.
- `BookRepository.java` — Spring Data JPA repository.
- `BookService.java` — transactional service layer.
- `BookController.java` — REST controller with Swagger/OpenAPI annotations.
- `GlobalExceptionHandler.java` — centralized `ProblemDetail` error handling.
- `ResourceNotFoundException.java` — application-specific 404 exception.

## Running the Application from Eclipse

1. Make sure the PostgreSQL Docker container is running.
2. In Eclipse, select `SwaggerDemoApplication.java`.
3. Choose `Run As → Java Application`.
4. Open Swagger UI in the browser:

```text
http://localhost:8080/swagger-ui/index.html
```

## Testing

### Eclipse JUnit/Coverage Run

In Eclipse, right-click `SpringBoot4FeaturesSwaggerSerenityPostgres-lib` in the Package Explorer and select:

```text
Coverage As → JUnit Test
```

The article target was more than 70% coverage.

`SwaggerDemoApplicationTests` is a minimal `@SpringBootTest` smoke test. Its `contextLoads()` method does not need explicit assertions; the test passes if the Spring application context starts successfully.

### Serenity Cucumber Tests

Open Cmder in the root Gradle project directory:

```text
SpringBoot4FeaturesSwaggerSerenityPostgres
```

Do not run the command from the parent `eclipse-workspace` directory.

Run:

```bash
gradlew :lib:clean :lib:cucumberTest :lib:aggregate --rerun-tasks
```

The Serenity report is generated at:

```text
lib/target/site/serenity/index.html
```

### Serenity REST Tests Without Feature Files

From the same root project directory, run:

```bash
gradlew :lib:clean :lib:test --tests "*WhenManagingBooks*" :lib:aggregate --rerun-tasks
```

This demonstrates Serenity REST testing directly from JUnit 6 / JUnit Jupiter tests, without Gherkin and without `.feature` files.

## Two Serenity Testing Styles Demonstrated

This project demonstrates two Serenity styles:

1. **Cucumber + Serenity** — uses `.feature` files written in Gherkin together with Java step definitions.
2. **JUnit 6 + Serenity REST** — uses ordinary JUnit/Jupiter test classes without `.feature` files.

Files involved:

- `RunCucumberTest`
- `BookStepDefinitions`
- `search_books.feature`
- `WhenManagingBooks`

Serenity can be integrated into a CI/CD pipeline, for example, a Jenkins-based pipeline, so that test results for each build can be documented.

## Notes on Swagger UI

Swagger UI is useful for quick manual testing before moving on to structured automated testing. It can also be useful for controlled smoke testing after deployment.

In production, use a dedicated test tenant, a dedicated test account, or clearly marked records that are isolated from real business data and excluded from normal reporting.
